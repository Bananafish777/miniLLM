## P0：分布式训练（JD 核心）

### Q1. 为什么需要分布式训练？单卡放不下了怎么办？

**一句话**：模型越来越大，单卡显存放不下权重/优化器/激活，只能把计算和显存切到多卡/多机。

**展开**：
- 三大瓶颈：**显存不足**（权重 + 优化器 + 梯度 + 激活 + KV Cache）、**算力不足**（单卡太慢）、**数据太大**（单机读不完）
- 三种解法：**数据并行**（复制模型，切数据）、**模型并行**（切模型，分到多卡）、**流水线并行**（切层）
- 记忆点：`显存 → 模型并行/ZeRO；速度 → 数据并行；两者都要 → 混合并行`

**追问应对**：若问"什么时候用哪种"→ 见 Q5。

### Q2. 数据并行 DDP 的原理？梯度怎么同步？

**一句话**：每张卡放完整模型、分到不同 batch，各自前向反向算出梯度，再**跨卡同步梯度**取平均后更新。

**展开**：
- 流程：每步每卡算局部梯度 → **AllReduce 求和/平均** → 各卡得到相同梯度 → 各自更新（模型保持一致）
- 同步实现：**Ring-AllReduce**（环状通信，每卡只和左右邻居传，带宽利用率高，通信量不随卡数增长）
- 关键开销：**梯度同步的通信量 = 参数量 × 2**（每步都要传），卡越多通信越贵 → 所以有了梯度累积、通信计算重叠

**追问应对**：若问"AllReduce 通信量"→ 每步传输约 `2 × 参数量`，与卡数无关，但环的时延随卡数线性增加。

### Q3. 张量并行 TP 是什么？切的是什么？

**一句话**：把**单层内的权重矩阵切开**分到多卡，每卡算一部分，通过通信拼接结果。

**展开**：
- 核心：把 `Y = X·W` 的矩阵乘法按**列切或行切**（列并行：每卡算 W 的一段列；行并行：每卡算 X 的一段行）
- 通信：每层前向/反向都要做 **AllReduce/AllGather**，通信极频繁 → 只适合**卡间高速互联**（如 NVLink 的机内多卡），不适合跨机
- 与 DP 区别：DP 是"模型复制 + 切数据"，TP 是"模型切分 + 数据全量"
- 记忆点：`TP 切权重、通信重、限机内`

**追问应对**：若问 TP 通信量 → 每层都通信，比 DP 频繁得多，所以 TP 卡数一般 ≤8，且要 NVLink。

### Q4. 流水线并行 PP 是什么？micro-batch 解决什么问题？

**一句话**：把模型**按层切成若干段**放到不同卡，数据像流水线一样逐段流过。

**展开**：
- 朴素 PP 的**气泡（bubble）**问题：同一时刻只有一张卡在算，其他卡空闲，利用率极低
- 解法：把 batch 切成更小的 **micro-batch**，像流水线一样多段同时填充，减少空闲 → **GPipe / PipeDream**（后者异步更激进的 1F1B）
- 记忆点：`PP 切层、气泡问题、micro-batch 填充流水线`

**追问应对**：若问 PP vs TP 通信 → PP 只在段边界传激活（通信量小、频率低），适合跨机；TP 每层都通信，只能机内。

### Q5. ZeRO 是什么？三阶段分别省了什么？

**一句话**：把**优化器状态、梯度、参数**分片到多卡，每卡只存一部分，用通信换取显存。

**展开**（三阶段，显存节省递增）：
- **ZeRO-1**：分片**优化器状态**（Adam 的 momentum/variance，通常占显存大头）
- **ZeRO-2**：再加分片**梯度**
- **ZeRO-3**：再加分片**模型参数**（每卡只存 1/N 参数，用到时从别卡 gather）
- 本质：**用通信量换显存**——卡越多每卡显存越省，但通信量上升
- 对比模型并行：ZeRO 是"数据并行的显存优化"，不切计算图，实现更通用

**追问应对**：若问 ZeRO vs TP → ZeRO 通信量更小（只在需要时分片参数），适合大规模数据并行；TP 通信重但单步快，两者可叠加（DeepSpeed 3D 并行）。

### Q6. 混合并行（3D 并行）怎么选型？

**一句话**：DP + TP + PP 三层叠加：TP 限机内（NVLink）、PP 跨机切层、DP 最外层扩数据。

**展开**：
- 选型原则：**机内优先 TP（高速互联），跨机用 PP 或 ZeRO-DP，最外层 DP 扩展吞吐**
- 典型配置（如千卡）：机内 8 卡 TP，机间 PP 切 8 段，再 DP 扩到 100 机 = 8×8×100
- 记忆点：`TP 机内、PP 跨机、DP 外层；先算单卡放得下，再算怎么扩`

**追问应对**：若问"单卡放不下一个 layer 怎么办"→ 那是极端 case，用 TP 进一步切 + 激活重计算 + offload。

### Q7. 通信原语有哪些？各自语义？

**一句话**：AllReduce（所有卡求和/平均，最常用）、AllGather（每卡数据拼起来全发）、ReduceScatter（求和后切片分发）、Broadcast（一卡广播）。

**展开**：
- **AllReduce**：所有卡都得到全局和 → DP 梯度同步的核心
- **AllGather**：每卡贡献一段，大家都拿到完整拼接结果
- **ReduceScatter**：先全局求和，再按段分到各卡（ZeRO 参数同步用）
- **Broadcast**：单点 → 全体
- 记忆点：`Reduce=求和、Gather=拼接、Scatter=分发、Broadcast=广播`，两两组合

**追问应对**：若问实现 → Ring（环，带宽优）vs Tree（树，时延优，多机常见）。

### Q8. 通信为什么是瓶颈？怎么优化？

**一句话**：每步都要同步梯度（DP）或每层都要通信（TP），通信时间没法被计算完全掩盖，就成瓶颈。

**展开**：
- 原因：**通信量 ≈ 参数量**（DP 每步 2×）、跨机还有网络时延（InfiniBand vs 以太网差数倍）
- 优化手段（按优先级）：
  1. **通信计算重叠**（反向算一部分就同步一部分，边算边传）
  2. **梯度累积**（多步小 batch 后一起同步，减少通信次数）
  3. **梯度压缩**（Top-K / 量化，损失精度换通信）
  4. 硬件：**NCCL + InfiniBand + 拓扑感知**（让通信走 NVLink/IB 最短路径）
- 记忆点：`重叠 > 减次数 > 压缩 > 换硬件`

**追问应对**：若问 NCCL → 全称 NVIDIA Collective Communications Library，是 GPU 集合通信标准实现，自动选最优算法（ring/tree）和拓扑。

### Q9. 显存优化还有哪些手段？

**一句话**：混合精度、梯度检查点、优化器分片（ZeRO）、offload。

**展开**：
- **混合精度**（fp16/bf16）：权重+激活半精度，显存减半，配合 loss scaling
- **梯度检查点（activation checkpointing）**：前向不存中间激活，反向时重算 → 用计算换显存
- **ZeRO**：见 Q5
- **CPU/NVMe offload**：把优化器状态/参数放到 CPU/磁盘（慢但能跑更大）
- 记忆点：`精度降、激活重算、状态分片、offload` 四件套

### Q10. 大模型训练流程与资源怎么估算？

**一句话**：显存 = 权重 + 优化器 + 梯度 + 激活 + 通信缓冲；先算单卡能否放下，再算集群规模。

**展开**：
- 经验值（fp16 混合精度，Adam）：**参数量 P（十亿）× 16~20 GB** 是训练时显存的粗略上限（含优化器 8 字节 + 梯度 2 + 权重 2 + 激活若干）
  - 例：7B 模型全参训练 ≈ 7×18 ≈ 126GB → 需要多卡 TP/ZeRO
- 训练时间估算：`总 token 数 × 每 token 计算量 / 集群总算力`
- 记忆点：`1B 全参训练约需 16~20GB 显存`（面试常用速算）

## P1：GPU 与 Kernel（JD 加分项）

### Q11. GPU 的计算模型？为什么能并行这么快？

**一句话**：GPU 是 **SIMT**（单指令多线程）：成千上万个轻量线程按 warp（32 线程）锁步执行，靠海量线程隐藏内存延迟。

**展开**：
- 层级：**grid（网格）→ block（块）→ thread**；block 分到 SM（流多处理器），block 内线程分组为 warp
- **显存层级**：全局显存（慢、大）→ L2 → 共享内存（shared memory，快、小）→ 寄存器
- 性能关键：**内存带宽往往才是瓶颈**（访存慢于计算），所以优化 = 减少全局访存、利用共享内存/寄存器
- 记忆点：`warp 32 线程、内存带宽是瓶颈、shared memory 是关键`

**追问应对**：若问 SIMT vs SIMD → SIMD 是向量指令，SIMT 是线程级锁步，程序员按标量写、硬件按 warp 并行。

### Q12. FlashAttention 为什么快？解决了什么？

**一句话**：标准注意力要反复读写 HBM 的注意力矩阵（O(n²)），FlashAttention 用**分块 + 融合 kernel**让计算"就地完成"，IO 从 O(n²) 降到 O(n²/M)。

**展开**：
- 问题：标准实现会显式构造 `QK^T` 的 n×n 矩阵再 softmax，**HBM 读写是 O(n²)**，而矩阵乘法本身 FLOPs 少 → **IO 受限**
- FlashAttention 三招：
  1. **Tiling（分块）**：把 Q/K/V 切成小 tile，逐块算 softmax，不落整个矩阵
  2. **在线 softmax**：用 running max/sum 增量归一化，避免二次读
  3. **Kernel 融合**：整个 attention 一个 CUDA kernel，中间结果全放 SRAM
- 结果：**显存占用从 O(n²) 降到 O(n)，速度提升 2~4 倍**
- 记忆点：`n² 显存 → 分块 + 在线 softmax + 融合`；这是 vLLM/SGLang 底层都在用的技术

**追问应对**：若问和 Paged Attention 关系 → 两者正交：FlashAttention 是单次 attention 的 kernel 优化，Paged Attention 是 KV 存储的分页管理，vLLM 里同时用。

### Q13. 为什么 kernel 优化能带来数量级提升？举一个思路

**一句话**：通用框架有很多**冗余访存和启动开销**，手写 kernel 能按硬件特性把数据留在快存储里、减少启动次数。

**展开**：
- 思路（以融合为例）：`逐算子执行`（每个算子读 HBM → 算 → 写 HBM）vs `算子融合`（一次读、算多个、少写）
  - 例：`LayerNorm + 残差 + 激活` 三算子融合成一个 kernel，少两次全局读写
- 其他：**利用 shared memory**（块内共享数据）、**向量化访存**（一次读 128bit）、**避免 warp divergence**（分支不同步）
- 记忆点：`访存冗余 → 融合；慢存储 → 快存储；多启动 → 少启动`

**追问应对**：若问"你做过 kernel 吗"→ 诚实说"我做过 MLX/Metal 层面的显存与调度优化（SGLang OOM 排查），CUDA 层面是原理理解，正在补"——见自我介绍诚实边界。
