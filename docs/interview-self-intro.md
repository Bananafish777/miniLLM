## 完整版（~2 分钟）

面试官您好，我是计算机工程硕士在读，研究生期间主要做大模型基础设施方向的工程实践。我的核心项目是一个**端到端的大模型推理基础设施平台**，覆盖微调、高性能推理、性能评测和部署监控全链路。

和您这个岗位最相关的，是我在**推理加速和性能分析**上的落地。我在 Apple Silicon 上用 **vLLM 和 SGLang 两个主流引擎**搭建了 OpenAI 兼容的推理服务，深入实践了 Paged Attention、Continuous Batching、KV Cache、Prefix Caching 这些优化机制。为了量化它们的收益，我**自研了一套三引擎对比的 Benchmark 系统**，用流式计时精确测吞吐、首 Token 延迟、Token 间延迟，并做了"客户端计数 + 服务端指标"的双通道交叉验证。

实测下来我印象很深：同样的 Qwen3-0.6B 权重，在并发 8 时 vLLM 能跑到约 480 tokens/s，是原生 Transformers 基线的 30 多倍；而 SGLang 在调参后单个并发点反而最高，但在更高并发下触发了 Metal 显存不足——这让我实际理解了不同引擎在**调度策略和显存管理**上的工程取舍，而不只是停留在概念层面。我后来把整套压测流程固化成了脚本，能一键复现。

在**平台化和调度**上，我用 Docker Compose 和 Kubernetes（Helm + Kueue GPU 队列 + HPA）做了完整的容器化部署和资源调度，配合 Prometheus/Grafana 做 GPU 指标和推理延迟的可观测性。另一个项目是做**大模型推理网关**，用 NER 模型做敏感数据的识别与脱敏，根据 prompt 风险做智能路由——这些让我对"服务端工程 + 大模型业务"的结合比较熟。

我也坦率说一下：**大规模分布式训练、通信优化和底层 kernel** 这一块是我相对薄弱的，我目前更多是推理侧和工程平台侧的实践。但我对这部分非常感兴趣，AI 系统的基础（PyTorch 训练流程、并行思想、显存/计算模型）我已经具备，也具备快速学习新框架的能力——这个岗位的"幕后推手"角色我很向往，也想借这个机会往算力基建这个方向深入。

## 精简版（~40 秒，用于开场或时间紧时）

我是计算机工程硕士，专注大模型基础设施方向。核心项目是端到端推理平台：用 vLLM/SGLang 搭 OpenAI 兼容推理服务，深入了 Paged Attention、Continuous Batching、KV Cache 这些机制；还自研了三引擎 Benchmark 系统，用双通道交叉验证精确测吞吐和延迟。实测同一权重下 vLLM 并发 8 达到约 480 tokens/s，是 Transformers 基线的 30 倍，也踩到过 SGLang 高并发 Metal 显存不足的问题。平台侧做了 Docker/K8s 部署、Kueue GPU 调度和 Prometheus/Grafana 监控。分布式训练和底层 kernel 是我正在补的方向，但 AI 系统基础和性能调优能力是扎实的。

## 使用要点

1. **数字要烂熟**：480 t/s、30 倍、双通道验证、Metal OOM——这些是"懂原理 + 有实操"的硬证据，追问时能展开
2. **主叙事**：推理加速 → 性能分析 → 平台化调度；**诚实边界**：分布式训练/kernel 是弱项但有意愿
3. **结合 JD 微调**：
   - 若面试官偏"推理引擎" → 多讲 Paged Attention/Continuous Batching 原理 + benchmark 口径
   - 若偏"调度/平台" → 多讲 Kueue/HPA/Docker 双轨 + 监控
   - 若偏"训练" → 主动引到 LoRA/QLoRA 微调实践，并坦诚训练侧经验边界
4. **不要背**：核心是"我真的做过、量过、调过"，讲的时候看面试官反应自然切换详略
